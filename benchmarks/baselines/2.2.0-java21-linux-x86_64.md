# 2.2.0 Java 21 Linux baseline

Recorded on 2026-09-07 with `package/run-benchmarks.sh full`.

- JDK: OpenJDK 21.0.12
- OS: Linux 7.0.0-31-generic, x86_64
- CPU: Intel Core i7-6700K, 4 cores / 8 threads
- JMH: 1.37, 3 warmups, 5 measurements, 2 forks

| Benchmark | Mode | Score | 99.9% error |
| --- | --- | ---: | ---: |
| `readConvertedRow` | average | 171.228 ns/op | 10.522 ns/op |
| `rebuildStructuredQuery` | average | 1275.633 ns/op | 86.217 ns/op |
| `renderLegacyUpdate` | average | 3139.366 ns/op | 120.847 ns/op |
| `renderPreparedUpdate` | average | 2078.876 ns/op | 89.800 ns/op |
| `borrowSelectAndReturn` | sample, 8 threads | 8.779 us/op | 0.201 us/op |
| `borrowUnderSaturation` | throughput, 8 threads | 37.519 ops/s | 0.943 ops/s |

Regular pool percentiles: p50 2.864 us/op, p90 3.468 us/op, p95 3.852
us/op, p99 10.112 us/op. Long-tail scheduling pauses are not portable across
hosts.

The saturation scenario recorded 335 successful borrows and 875 timeouts
across both forks, a 72.31% timeout share. This is an overload diagnostic, not
a recommended production pool size.

The portable same-run ratios were 0.662 for prepared/legacy rendering, 0.406
for query-rebuild/legacy rendering, and 0.055 for row-conversion/legacy
rendering. All were within the release budget. Absolute results should only be
compared on equivalent hardware, JDK, operating system, and power profile.
