# AgtySQL Session API

This document fixes the public session/JDBC contract of `AgtySQL`.

Purpose:

- describe how to use `AgtySQL` as a high-level API;
- describe how to use `AgtySQL` as a low-level JDBC entry point;
- define resource lifecycle;
- provide a base for the full user guide.

## Roles of `AgtySQL`

`AgtySQL` supports two main usage modes.

### 1. High-level mode

Used for standard scenarios:

- `fetch(...)`
- `listArray(...)`
- `insert(...)`
- `insertAndGet(...)`
- `update(...)`
- `updateAndGet(...)`
- `delete(...)`
- `countRows(...)`

In this mode the library:

- builds SQL;
- talks to the driver;
- converts the result to `SqlRow`;
- manages the typical lifecycle of temporary JDBC objects.

Entity/model convenience layer (`fetch(..., entity)`, `insertEntity*`,
`saveEntity*`) remains a supported part of the high-level API.

### 2. Low-level session/JDBC mode

Used when direct JDBC control is needed:

- `getConnection()`
- `getStatement()`
- `prepareStatement(...)`
- `executeBatch(...)`
- `getGeneratedKeys(...)`
- `openCursor(...)`
- `beginTransaction()`
- `setAutoCommit(...)`
- `commit()`
- `rollback()`
- `setFetchSize(...)`

This mode is intended for:

- custom SQL;
- manual `PreparedStatement` work;
- batch execution;
- generated keys;
- streaming/cursor scenarios;
- explicit transaction control.

Deprecated raw `ResultSet` helper methods such as `executeQuery(...)`,
`executeResultSet(...)`, `statementExecuteQuery(...)` and similar are no longer
the target API for new code.

For new code prefer:

- `prepareStatement(...).executeQuery()`
- `getStatement()`
- `openCursor(...)`

## Supported low-level scenarios

### Connection

```java
AgtySQL sql = new AgtySQL("mysql");
Connection connection = sql.getConnection();
```

Use it when:

- you need integration with third-party JDBC code;
- you need JDBC-specific connection settings;
- you need to pass a connection to external code.

### Statement

```java
try (Statement statement = sql.getStatement()) {
    statement.execute("SELECT 1");
}
```

### PreparedStatement

```java
try (PreparedStatement prepared = sql.prepareStatement(
        "INSERT INTO {users} (name, age) VALUES (?, ?)"
)) {
    prepared.setString(1, "Alex");
    prepared.setInt(2, 30);
    prepared.executeUpdate();
}
```

Important variants:

- `prepareStatement(query)`: query goes through the rebuild pipeline;
- `prepareStatement(query, boolean noRebuildQuery)`: rebuild may be disabled;
- `prepareStatement(query, autoGeneratedKeys)`: helper for generated keys;
- `prepareStatement(query, autoGeneratedKeys, noRebuildQuery)`: full control.

### Generated keys

```java
try (PreparedStatement prepared = sql.prepareStatement(
        "INSERT INTO {users} (name) VALUES (?)",
        Statement.RETURN_GENERATED_KEYS
)) {
    prepared.setString(1, "Alex");
    prepared.executeUpdate();

    SqlRow keys = sql.getGeneratedKeys(prepared);
}
```

Use this when you need the JDBC-style generated-key flow below
`insert(... setReturnLastInsertId(true))`.

### Batch

```java
int[] result = sql.executeBatch(List.of(
        "INSERT INTO {users} (id, name) VALUES (1, 'A')",
        "INSERT INTO {users} (id, name) VALUES (2, 'B')"
));
```

### Cursor / streaming

Two official variants exist:

- direct JDBC `ResultSet`;
- library `AgtySqlCursor`.

Direct JDBC:

```java
try (PreparedStatement prepared = sql.prepareStatement(
        "SELECT * FROM {users} ORDER BY id"
);
     ResultSet resultSet = prepared.executeQuery()) {

    while (resultSet.next()) {
        long id = resultSet.getLong("id");
    }
}
```

Library cursor:

```java
try (AgtySqlCursor cursor = sql.openCursor(
        Arguments.builder()
                .setTable("{users}")
                .setOrderBy("id ASC")
)) {
    SqlRow row;
    while ((row = cursor.next()) != null) {
        long id = row.getLong("id");
    }
}
```

## Ownership and lifecycle

### High-level methods

Examples:

- `fetch(...)`
- `listArray(...)`
- `insert(...)`
- `update(...)`

Resource owner:

- the library.

### Low-level methods

Examples:

- `getStatement()`
- `prepareStatement(...)`
- direct JDBC `ResultSet`

Resource owner:

- the developer.

### `AgtySQL` instance

The `AgtySQL` object itself should be closed by application code:

```java
AgtySQL sql = new AgtySQL("mysql");
try {
    // work
} finally {
    sql.close();
}
```
