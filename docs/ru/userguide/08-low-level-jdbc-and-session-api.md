# 08. Низкоуровневый JDBC и Session API

### `Connection`

```java
Connection connection = sql.getConnection();
```

Использовать, когда нужно:

- интегрироваться с внешним JDBC-кодом;
- настраивать connection вручную;
- работать ниже уровня high-level API.

### `Statement`

```java
try (Statement statement = sql.getStatement()) {
    statement.execute("SELECT 1");
}
```

### `PreparedStatement`

```java
try (PreparedStatement prepared = sql.prepareStatement(
        "INSERT INTO {users} (name, age) VALUES (?, ?)"
)) {
    prepared.setString(1, "Alex");
    prepared.setInt(2, 30);
    prepared.executeUpdate();
}
```

Поддерживаются overload-методы:

- `prepareStatement(query)`
- `prepareStatement(query, boolean noRebuildQuery)`
- `prepareStatement(query, int autoGeneratedKeys)`
- `prepareStatement(query, int autoGeneratedKeys, boolean noRebuildQuery)`

`noRebuildQuery = true` использовать только для уже готового SQL.

### Выполнение произвольного SQL

```java
boolean ok = sql.execute("DELETE FROM {temp_users} WHERE [expired] = true");
```

Есть и overload:

```java
boolean ok = sql.execute("SELECT 1", true);
```

### Обновление данных вручную

```java
Long affected = sql.executeUpdate(
        "UPDATE {users} SET [active] = false WHERE [expired] = true"
);
```

### Deprecated execute/result-set helpers

Следующие методы на дату `2026-08-03` считаются deprecated и сохраняются как
compatibility API:

- `statementExecute(...)`
- `statementExecuteResultSet(...)`
- `statementExecuteQuery(...)`
- `statementExecuteUpdate(...)`
- `statementExecuteLargeUpdate(...)`
- `executeResultSet(...)`
- `executeQuery(...)`

Для нового кода предпочтительно:

- `execute(...)` для простого фасадного выполнения;
- `executeUpdate(...)` для update-like SQL;
- `getStatement()` или `prepareStatement(...)` для прямого JDBC-контроля;
- `openCursor(...)` для streaming-сценариев.

### Batch execution

```java
int[] result = sql.executeBatch(List.of(
        "INSERT INTO {users} (id, name) VALUES (1, 'A')",
        "INSERT INTO {users} (id, name) VALUES (2, 'B')"
));
```

При необходимости rebuild можно отключить:

```java
int[] result = sql.executeBatch(List.of(
        "INSERT INTO users (id, name) VALUES (1, 'A')",
        "INSERT INTO users (id, name) VALUES (2, 'B')"
), true);
```

### Generated keys

```java
try (PreparedStatement prepared = sql.prepareStatement(
        "INSERT INTO {users} (name) VALUES (?)",
        Statement.RETURN_GENERATED_KEYS
)) {
    prepared.setString(1, "Alex");
    prepared.executeUpdate();

    SqlRow keys = sql.getGeneratedKeys(prepared);
}
```

Это JDBC-style путь, если нужен контроль ниже уровня
`insert(... setReturnLastInsertId(true))`.

### Fetch size

```java
sql.setFetchSize(100);
int fetchSize = sql.getFetchSize();
```

Значение применяется к создаваемым библиотекой `Statement`.
